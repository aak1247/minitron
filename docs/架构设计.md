# 运行时与应用拆分实现

## 发行与加载

应用目录只有 shell.exe、shell.toml 和 resources。asar 和 unpacked 由纯资源构建器生成，不包含 Electron。启动器把 app.asar 绝对路径作为位置参数交给共享的官方 Electron，不依赖 resources-path 开关。

process.defaultApp=true。process.resourcesPath 属于 runtime；业务文件从 app.getAppPath()/__dirname 解析，动态库使用 app.asar.unpacked 中的真实路径。

## 共享目录

默认在当前用户本地数据目录的 SharedElectron，ELECTRON_RUNTIME_ROOT 可覆盖。runtime key 是 platform triple + 精确 Electron x.y.z，不同版本/架构不混用。

~~~
SharedElectron/
  versions/<platform>/v<version>/
    electron.exe / Electron.app / electron
    resources/default_app.asar
    install.json
  refs.json
  locks/
  leases/<key>/
  staging/<key>/<artifact-sha>/download/
~~~

官方默认加载器是 default_app.asar。Windows/Linux 位于 resources；macOS 位于 Electron.app/Contents/Resources。macOS framework 数据文件使用 framework Versions/A/Resources 的实际目录。

安装过程按 runtime key 排他锁串行。完整包下载使用固定 artifact 缓存以支持续传，解压采用唯一临时目录。验证关键结构、原始 ZIP 的 SHA256、大小及关键文件后写 install.json，最后在同一文件系统提交版本目录。marker 的 platform/version/hash 必须匹配，半安装目录不能被 locate 返回。

引用登记按规范化安装目录区分，同 app_id 多份安装也独立。每次登记替换当前安装的完整依赖集，包含 active、previous 和 pending。卸载只撤销本安装。空引用条目保留为待 GC；运行时使用锁或实际 Electron PID 仍活时不删除，之后的登记/卸载会重试回收。损坏 refs/lease 报错保留文件。

使用 lease 是 OS 共享锁加 owner/child PID 与进程创建时间 sidecar。即使壳被强制终止，也能发现仍在运行的 Electron；PID 重用通过创建时间区分。非 Windows 保守使用 PID，不声称已完成其他平台的进程身份验收。

## 启动与锁序

本安装的 updates/application.lock 在一次 Electron 生命周期内保持排他，阻止同一安装同时激活或卸载；不同应用仍可同时共享 runtime。

本地 Release 和 runtime 就绪后不在线阻塞，拉起 Electron 后再检查更新。首次缺运行时才下载。--offline 不访问更新源；--no-update 允许补齐 runtime 但禁止后台应用更新。

启动器等待真实 Electron 子进程并保留退出码。慢速 Slint UI 只负责准备运行时，成功后退出 UI event loop，再由主协调器启动并等待 Electron。错误 UI 可重试，不能因为隐藏窗口而提前结束子进程管理。

业务状态写入使用 updates/state.lock，背景下载另用 staging.lock，不持整个网络下载阶段的 state.lock。引用变更与 pending 提交处于同一状态事务。基础锁序为应用生命周期 → 业务状态 → runtime registry → runtime usage；安装 runtime 的安装锁及 usage 排他锁不在持 registry 锁时获取。

## 应用更新

Release = 应用版本 + RuntimeKey + 资源目录 + 原始更新 ZIP 的 SHA256。初始 resources/ 不迁移；缺 active.json 时从 shell.toml 解析基线 Release。

~~~
updates/
  active.json
  pending.json
  transaction.json
  ready/
  releases/<app-version>/<zip-sha>/resources/
  staging/
~~~

后台只准备完整候选版本，包括其精确 runtime。asar、unpacked 和 release marker 放入同一不可变目录；准备成功后写 pending 并登记引用。原安装没有 ZIP hash，因此同 app_version+runtime 视为基线相同版本；已发布版本不可更换 runtime 或 ZIP，需提升 app_version。

下一次启动获得本安装排他锁后激活：记录 prepared → 原子切换 active/previous → awaiting_health → 启动子进程。transaction 保存 txid、from/to、PID、创建时间、ready 路径和退出码，用于中断恢复。旧资源目录及其 runtime 保留供回滚，回滚只切指针，不原地复制 DLL。

应用收到 ERS_READY_FILE 与 ERS_RELEASE_TXID 后可在页面/preload/IPC 初始化完成时原子写：
{"txid":"对应事务ID","ready":true}

示例已实现该协议。显式 ready、正常零退出或十秒存活宽限期都可确认启动；后两者只是未接协议应用的弱判据。未确认的新版本非零退出会恢复整个 previous Release；已确认后的晚期崩溃不自动回滚。崩溃恢复同时比对 active 和 transaction，避免把仍在运行的尝试当成失败。

## 下载、格式与信任

Artifact 提供 URL、64位十六进制 SHA256 和精确字节数。部分文件名根据 artifact 身份生成；续传只接受起点正确的206/Content-Range，服务器返回200时从头覆盖。416、截断、长度不符、哈希不符都有明确处理，校验后才返回完整 artifact。

解压验证路径在 staging 内，不允许 ../、绝对路径、越界链接或通过已存在链接写出 staging。Windows 拒绝符号链接；Unix 仅允许归档内的受限相对链接，以兼容官方 macOS bundle。

清单采用严格 JSON parser：拒绝重复键、浮点数和超大清单。校验 app_id、严格版本、目标平台、URL、hash 和 size。HTTPS 为正式传输；loopback HTTP 需要 allow_localhost_http=true。

manifest.runtime 绑定候选 app，manifest.runtimes 保存历史版本 artifacts。不能把新清单的 runtime 版本直接写入旧 Release。shell 字段为可选的分平台壳 artifacts，min_stub_version 要求最低壳版本。

Ed25519 签名载荷是移除顶层 signature 后的 JSON，递归按对象键排序、无空白、UTF-8；数组保持顺序。发布器只生成安全整数，Rust parser 拒绝浮点，metadata 键使用 ASCII。signature 为 base64 签名字节，manifest_public_key 为 base64 原始32字节公钥。配置公钥后必须验签，artifact SHA 由已验证的清单提供。

## 壳自更新

新壳先下载、复验 hash 并执行 --version 核对清单版本，避免错误 artifact 导致循环更新。旧壳复制到独立临时目录作为 copier，ticket 包含目标/待替换/备份绝对路径、parent PID及创建时间、hash、重启参数和结果路径。

copier 验证 ticket 路径边界，等待原父进程真正退出；再取得 application.lock、复验 hash、备份、有限重试替换目标并重启。Windows 使用 MoveFileExW 的 REPLACE_EXISTING/WRITE_THROUGH。失败保留旧目标或恢复备份。updates/selfupdate.log 和 selfupdate-*.result.json 留存阶段结果；不依赖 copier 临时目录中的 shell.toml。

## 验证边界

Windows x64 采用真实官方 Electron ZIP、隔离共享目录、本地 HTTP 源和临时签名密钥端到端验证。测试涵盖 GUI 下载路径、页面/preload/IPC、真实 native addon、并发共享、卸载、离线、应用更新与回滚、两个 runtime 版本和真实壳替换。

macOS/Linux 的路径与源码兼容支持不等于已通过对应平台的发行验收。系统签名、macOS 公证、真实生产 CDN 与发布密钥由发布环境提供。
